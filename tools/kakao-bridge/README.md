# asdf 카톡 OCR → 나이테 베타

Windows PC에서 **별도 창으로 연 카카오톡 `asdf` 방**만 직접 캡처합니다. Gemini는 글자·보낸 사람·메시지 날짜·시각을 읽고, 베타 브라우저가 내용을 검증한 뒤 기존 Firebase 권한으로 저장합니다. 정식 예약표와 Firebase 규칙은 바꾸지 않습니다.

## 이 PC에서 실행

저장소 폴더에서 PowerShell로 실행하세요. 현재 PC에는 `.venv`와 캡처 라이브러리를 설치해 두었습니다.

```powershell
./tools/kakao-bridge/start.ps1
```

1. Windows **사용자 환경변수** `GEMINI_API_KEY`에 [Google AI Studio에서 발급한 키](https://aistudio.google.com/apikey)를 저장합니다. 채팅·소스·브라우저에는 키를 입력하지 마세요. 처리기는 실행 중에도 새로 설정한 사용자 환경변수를 읽습니다.
2. 카카오톡의 `asdf` 방을 따로 열고 대화 맨 아래로 갑니다. 최소화하지 않습니다. 다른 창에 가려져 있어도 캡처할 수 있습니다.
3. 같은 PC에서 [GitHub 베타 공유 페이지](https://gnu-naite.github.io/naite-reservation/beta/)를 열고 **이 PC의 OCR 연결**을 누릅니다. Chrome·Edge에서 로컬 네트워크 접근을 물으면 허용합니다. 하단 **관리자 로그인** 또는 **카톡 닉네임 연결**을 완료해야 저장됩니다. <http://localhost:5173/beta/>도 그대로 사용할 수 있으며, 로컬 주소에서는 관리자 로그인이 필요합니다. 배포 주소와 localhost 로그인은 별개이고, API 키만으로 Firebase 쓰기 권한이 생기지는 않습니다.
4. 본인 말풍선에는 닉네임이 없으므로 **내 카톡 닉네임**을 입력합니다. 이 테스트는 `김동하`입니다. 다른 사람이 보낸 메시지는 화면의 카톡 닉네임을 사용합니다.
5. **새 메시지 자동 처리 시작**을 누르고 **캡처 영역 확인**을 펼칩니다. 날짜 구분선·작성자·말풍선·보낸 시각이 모두 보이고 입력칸은 보이지 않게 위/아래 제외 높이를 맞춥니다. 여백이나 닉네임을 바꾸려면 **중지** 후 다시 시작합니다. 창 크기를 바꾼 뒤에는 다시 확인합니다. 이 PC의 475px 너비 창에서는 위 78px / 아래 150px를 확인했습니다.
6. 시작할 때 보이던 대화는 기준 화면으로만 기록하고 카드에 **자동 처리 제외**로 표시합니다. 이후 새 말풍선을 처리합니다. 실행 중에는 시작 버튼이 **자동 처리 중**으로 표시되며 다시 누를 수 없습니다. 이미 보이는 테스트 문구도 처리하려면 **현재 화면도 읽기**를 누릅니다. 이 버튼은 보이는 예약·취소 메시지의 저장도 진행하므로 테스트 화면에서만 누르세요.

브라우저와 처리기, PC를 계속 켜둬야 자동 저장됩니다. 최소화·창 닫기·네트워크 장애·무료 할당량 제한 중에는 인식을 보류합니다. 무료 제한은 새 메시지를 많이 보내거나 화면을 움직여도 요청을 최소 30초 간격으로 제한하고 실패 시 60초 이상 기다립니다.

## 처리 기준

- 연도가 없으면 한국 시간의 현재 연도, 월이 없으면 현재 월을 씁니다. 화면에 날짜 구분선이 없어도 이 기본값을 사용합니다. `14일 수 16-17시 하이라이트 합주임당` → 현재 연월의 14일, 하이라이트, 합주, 카톡 닉네임, **한 번만**. 날짜와 요일이 다르면 확인 대기. 새해에는 기본 연도가 자동으로 바뀝니다.
- `10/10 토요일`, `10.10 토`, `10/10일`도 현재 연도의 10월 10일로 읽고, 요일이 있으면 확인합니다. `합주`·`추합`·`추가합주`·`추가 합주`는 모두 **합주** 예약입니다.
- `금일`·`오늘`은 한국 시간의 오늘, `내일`은 하루 뒤입니다. 월말·연말에도 다음 달·다음 해로 넘어갑니다. `안해요`·`안합니다`(띄어쓰기 포함)는 취소입니다. `오늘 범람 안해요`는 오늘 범람 예약 한 건, `내일 19~20 안합니다`는 내일 해당 시간 한 건을 찾습니다. `취소 안해요`·`취소 안합니다`는 취소를 부정하므로 보류합니다.
- 날짜 없이 `월`·`화`·`수`·`목`·`금`·`토`·`일` 또는 `월요일` 등으로 쓰면 **한국 시간의 이번 주(월요일~일요일)** 날짜입니다. `이번 주 토요일`·`이번주 일`도 같습니다. 2026년 10월 10일 기준 `토 15~16 멸종 합주`는 10월 10일, `일요일 멸종 합주 취소`는 10월 11일입니다. 이번 주에 이미 지난 요일의 새 예약은 보류합니다. 다음 주·지난 주·매주는 자동으로 추측하지 않고 정확한 날짜를 확인합니다.
- 시간이 없는 취소는 제목 끝의 `추가`·`합주`·`추가합주`·`추합`·`예약` 표시와 띄어쓰기·영문 대소문자 차이를 제외한 팀명으로 비교합니다. `오늘 멸종 합주 취소`로 오늘의 `멸종 추가` 예약을 찾을 수 있습니다. 같은 날짜에 일치하는 후보가 여러 건이면 보류합니다. 다른 팀 이름의 일부만 일치하거나 오타가 있는 경우에는 시간을 적어야 합니다. 기존 예약 제목은 유지됩니다.
- `19:00~20:00`, `19시부터20시까지`, `오후7~8시`, `12~14`처럼 ‘시’ 없는 시간도 인식합니다. 오전·오후 표기가 없으면 **24시간제**이므로 `7~8`·`7 8`은 **07:00~08:00**, **12시는 정오(12:00)**입니다. `19시반20시반`·`19시반~20시반`은 **19:30~20:30**으로 읽습니다. `오전12시`는 자정(00:00)입니다. 종료 시간이 시작 시간보다 이르면 다음 날 종료로 처리합니다.
- `10/11 11~12 far away from the home 합주` → 10월 11일 11:00~12:00, 팀명 **far away from the home**, 합주, 카톡 닉네임, **한 번만**. 영어 팀명과 단어 사이 공백을 유지합니다.
- `레슨 하겠습니다` → 사용 목적과 팀명 모두 **레슨**. 날짜·시간·닉네임도 필요합니다.
- 합주·레슨 키워드가 없으면 **기타** 예약으로 읽고, 팀명도 없으면 **기타**로 저장합니다. `10/11 7 8` → 07:00~08:00, 팀명·목적 **기타**. `[예약] 2026-10-12 / 19:00~21:00 / 나이테팀`도 목적은 **기타**입니다. `기타레슨`의 기타는 악기입니다. 신규 레슨의 팀명·사용 목적은 **레슨**으로 저장합니다.
- `금일 20~21시 취소` → **한국 시간의 오늘 날짜**, **20:00~21:00**에 정확히 일치하는 한 건만 취소합니다. `10/11 11~12 faw away 합주 취소`도 같은 시간의 `far away`를 취소하며 팀명·목적·닉네임을 비교하지 않습니다. `10/11 범람 합주 취소`처럼 시간이 없으면 **날짜·팀명**이 일치하는 한 건만 취소합니다. 영문 대소문자·연속 공백 차이는 무시하지만 시간이 없는 팀명 오타는 추측하지 않습니다. `THE 16-17`처럼 팀명 뒤에 단위 없는 숫자 구간이 오면 전체 팀명으로만 찾고, 일치하지 않으면 보류합니다. 시간을 팀명 앞에 쓰거나 `11시~12시`처럼 단위를 붙이면 시간으로 찾습니다. 같은 날짜 같은 팀 예약이 여러 건이면 시간을 확인해야 합니다. 고정 예약이어도 해당 날짜 한 건만 취소합니다.
- 예약 추가는 등록된 모든 카테고리의 시간과 겹침을 검사하고, 일부라도 겹치면 **반려**합니다. 겹치지 않는 기타 예약도 **한 번만** 저장합니다. 수정은 예약 화면에서 해당 날짜·시간의 예약을 선택해 직접 처리합니다. 채팅의 수정·변경 문구는 자동 실행하지 않습니다.
- 취소 대상 0건 또는 여러 건, 시간이 없는 취소의 팀명 누락, 새 예약의 닉네임 없음, 잘린 문장, 질문·부정·금지·변경·읽기 불확실한 내용, 예약 날짜 누락·신규 예약 시간 누락·불완전한 취소 시간은 **확인 필요**로 남깁니다. 카드에서 값을 확인하고 처리하거나 제외합니다.
- 날짜 구분선이 없는 경우 자동 모드에서는 직전 화면의 마지막 말풍선 뒤에 새로 도착하고 현재 한국 시각과 3분 이내인 메시지에만 오늘 날짜를 쓸 수 있습니다. 기준 말풍선이 없어지면 자동으로 과거 대화를 처리하지 않습니다. 대화 맨 아래를 유지하고, 누락 내용은 현재 화면 읽기와 확인 폼을 사용하세요.
- 취소 대상이 저장 직전에 수정되면 삭제를 멈춥니다. 이미 저장을 시작한 작업은 같은 문서만 재시도합니다.

## 키·이력·한계

기본 모델은 이미지 입력과 구조화 출력을 지원하는 [Gemini 3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)입니다. [무료 등급과 데이터 이용 정책](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite)은 발급한 프로젝트의 상태를 확인하세요. 캡처한 채팅 영역은 Gemini에 전송됩니다.

키는 환경변수에서만 읽고 로그·URL·브라우저·Firestore에 남기지 않습니다. HTTP 서버는 `127.0.0.1`에만 바인딩하고 로컬 페이지와 `https://gnu-naite.github.io`의 OCR API 요청만 허용합니다. 다른 사이트와 외부 PC에서는 처리기에 접근할 수 없고, 저장 요청에는 매 실행마다 바뀌는 로컬 세션 토큰도 필요합니다. 창 이미지는 메모리에만 있으며, 인식한 원문·닉네임·처리 상태는 `.local/state.json`에 저장합니다. 이 폴더와 `.venv`는 Git에서 제외됩니다. **이력을 지우면 과거 대화를 다시 처리할 수 있으므로, 운영 중에는 지우지 마세요.**

OCR 특성상 글자를 잘못 읽을 수 있습니다. 같은 사람이 같은 분에 보낸 동일 원문은 한 메시지로 취급합니다. 수동 예약을 포함한 동시 예약 경쟁은 기존 앱처럼 클라이언트에서 검사하므로 서버 수준의 시간 잠금은 없습니다. 최초 테스트에서는 인식 결과와 베타 예약표를 함께 확인하세요.

## 새 PC 설치 / 검증

Python 3.12 이상이 설치된 Windows에서:

```powershell
py -3 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r tools/kakao-bridge/requirements.txt
./tools/kakao-bridge/start.ps1
```

```powershell
node tools/chat-parser.test.mjs
node tools/chat-bridge.test.mjs
node --experimental-vm-modules tools/chat-store.test.mjs
node tools/chat-variants.test.mjs
./.venv/Scripts/python.exe -X utf8 -m unittest discover -s tools/kakao-bridge -p test_bridge.py
```

GitHub 공유 페이지를 켜둔 캡처 PC에서 자동 반영할 수 있습니다. 별도의 localhost 페이지는 켜둘 필요가 없습니다. PC의 OCR 처리기와 asdf 창은 계속 실행해야 하며, 다른 PC·휴대폰에서는 저장된 예약표만 공유됩니다. 공유 페이지 연결이 막히면 최신 Chrome·Edge와 [로컬 네트워크 권한 안내](https://developer.chrome.com/blog/local-network-access)를 확인하세요.
